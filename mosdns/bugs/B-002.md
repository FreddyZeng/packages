# Bug Report: B-002 | geodat_update Silent Failure on Missing Target Directory

## 1. 现象 (Symptoms)
- **表层症状**: 用户提示“/usr/share/v2ray/*.dat 的更新也需要注意”。在观察其上下文中发现，当源 `dat` 文件正常下发时，并未成功完成对现有 OpenWrt 系统 `/usr/share/v2ray/` 文件夹的投递，从而使 mosdns 获取到错误的路由数据。
- **系统表现**: 如果用户系统中尚未安装依赖包创建过 `/usr/share/v2ray/` 文件夹（或原本被删除），`\cp -a "$TMPDIR"/* /usr/share/v2ray` 文件复制步骤发生致命失败（提示 target not a directory），可是脚本并未捕获异常便清理了缓存 `$TMPDIR` 然后返回成功代码，导致更新静默失败。

## 2. 根因分析 (Root Cause)
- **直接触发点**: `mosdns.sh` 在执行解包移动 `geodat_update()` 时缺少对目标文件夹是否存在的守护，同时使用了非容错的复制命令。
- **根本漏洞**: 缺少了 `mkdir -p /usr/share/v2ray` 导致写入目标可能因前置依赖缺失而崩溃。而且未接载复制动作的 `[ $? -ne 0 ]` 断路器，将一个未完成的“半成品”操作对外报了成功信号，使得更新计划失败变相成了隐藏“地雷”。

## 3. 防御性修复 (Resolution)
1. **预防前置依赖缺失**: 补全 `mkdir -p /usr/share/v2ray` 无论它是否存在，保障投递的最终层级绝对生成。
2. **强制致命拦截**: 检测 `\cp -a` 复制动作后的 `$?`。一旦检测出并非 `0`，立即附带错误追踪输出到控制台 `[UPD-B002-①]`，及时清除残留临时文件然后硬性 `exit 1`，彻底掐灭错误数据流入后台服务重启引发的问题。
