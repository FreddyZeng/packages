# Bug Report: B-003

## 1. 根本目标 (Target)
在通过 `mosdns.sh geodata` 或 `adlist_update` 更新远程 GeoData (v2ray/*.dat) 及广告拦截规则 (adlist) 时，确保：
**只有新数据下载并校验成功后，才执行对旧数据的替换。**

## 2. 表层症状 (Symptoms)
原版脚本对于 AdList 规则，采取了先清空目标文件夹 (`rm -rf /etc/mosdns/rule/adlist/*`)，再执行拷贝 (`\cp $AD_TMPDIR/* ...`) 的危险操作。如果此时拷贝失败（如磁盘占满等不可抗力异常），将会彻底丢失原有的广告规则配置。对于 GeoData 的拷贝动作同理，如果在不可靠的环境下执行覆盖，依然有一定的损坏风险。

## 3. 根因分析 (Root Cause)
脚本中缺乏安全的目录切换策略。过早销毁了原有规则集合以期获得纯净的替换环境，导致可用性中断（Dirty Read/Write）。

## 4. 实施修复 (Resolution)
进行了**精简安全更新机制重构 (Atomic File Switch Strategy)**，取消了复杂的 `.bak` 原地备份。
- **针对 GeoData**:
  保留 `geodat_update` 中既有逻辑，所有的 `geoip.dat` 与 `geosite.dat` 都在隔离的随机临时目录 (`$TMPDIR`) 内下载并执行 `.sha256sum` 严格哈希图灵校验。
  当且仅当二者均通过安全校验时，才触发最后一行的 `\cp -a "$TMPDIR"/* /usr/share/v2ray` 进行直接替换。未通过校验的文件只会被直接 `rm -rf` 销毁，绝对不会染指 `/usr/share/v2ray` 文件夹中的旧数据。
- **针对 AdList (B-003-②)**:
  采用原子路径切换替换先删后写模式。
  1. 下载的新规则首先移入 `/etc/mosdns/rule/adlist.new` 影子文件夹中。
  2. 若转移操作成功 (`$? -eq 0`)，此时新规则已构建完毕，利用极短时间的 `rm -rf` 随之马上结合 `mv` 指令，实现旧目录向新目标的闪电切换。
  3. 若构建失败，影子文件夹直接废弃，现网业务规则毫发无损。

## 5. 链路与影响验证
该机制利用最精简的基础 shell 指令达到了高效的防错容忍力。既不给路由器的极小存储空间带来保留双份 `.bak` 的额外容量负担（即 KISS 原则），又做到了在一切失败的情况下“不污染旧数据”。
