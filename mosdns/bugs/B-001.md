# Bug Report: B-001 | mosdns PROCD Restart Loop on GeoData Failure

## 1. 现象 (Symptoms)
- **表层症状**: 用户反映“mosdns 更新GeoIP & GeoSite 数据库 失败后, 一直自动重启”。
- **系统表现**: mosdns 进程因为缺少所需数据无限崩溃，随着 OpenWrt 系统 `procd` 看门狗不断且频繁地尝试重启 `mosdns` 实例，导致系统死循环或资源被无限重试耗尽。

## 2. 根因分析 (Root Cause)
- **直接触发点**: `mosdns.sh geodata` 若更新失败，因网络等原因，下载的文件可能有问题。或者对于全新安装未使用过更新功能，自带的 `/usr/share/v2ray/*.dat` 不存在。
- **机制漏洞**: `/etc/init.d/mosdns` 这份 init 脚本中，在执行 `start_service` 阶段，总是无条件先通过 `v2dat_dump` 删除历史导出的规则（`rm -f /var/mosdns/geo*.txt`），然后执行解包 `v2dat unpack`。
- **根本错误**:
  1. 如果解包失败（受损或文件本身缺失），那些强依赖的 `.txt` 数据不会被生成出来。
  2. 生成的硬编码配置文件 `var/etc/mosdns.json` 将依旧包含 `/var/mosdns/geoip_cn.txt`。这直接导致 `mosdns` 本体启动时崩溃报错 1。
- **放大机制**: `start_service` 末尾通过 `procd_open_instance mosdns` 及设置 `procd_set_param respawn` 托付给了 procd 守护进程。守护进程发现 mosdns 遇到异常终止（错误1），就会不停地进行 `respawn` 试图恢复，但由于缺失的文件并没有得到补充，因此进入了无穷尽的“崩溃 -> procd自动重启 -> 再次崩溃”死亡循环中。

## 3. 防御性修复 (Resolution)
1. **强行切断重启循环**: 修改 `root/etc/init.d/mosdns` 的 `start_service()` 定义，在交接给 `procd_open_instance` **之前**建立强校验。如果通过 `${CONF}` 指向我们生成的 JSON，首先检查 `geosite_cn.txt` 和 `geoip_cn.txt` 的存在及文件内容大小（`! -s`）。一旦触发缺失，直接往 `$($MOSDNS_SCRIPT logfile)` 注入标准形式的 Tag 日志，并通过 `return 1` 强行终止 `start_service` 过程。既然不曾注册过 instance，`procd` 也绝不会执行自动重启。
2. **修复子进程清理陷阱**: `mosdns.sh` 取消隐患极大的短路运算符判断 `[ $? -ne 0 ] && rm -rf "$TMPDIR" && exit 1`，将其用完备的 Bash `if..then` 替代，使得任何情况下都能百分百拦截住错误解包或错误文件的注入执行。同时也在这部分逻辑引入日志追踪 ID，以备未来二次分析。
