# Bug Report: B-004

## 1. 根本目标 (Target)
在通过 `mosdns.sh geodata` 更新远程 GeoData (也就是 `/usr/share/v2ray/*.dat`) 数据时，确保：
**抵御物理断电级别的数据损坏，使用同一硬盘分区下的 `rename(2)` 系统调用（Shadow-folder atomic switches 影子替换法）保证文件更新的原子性。**

## 2. 表层症状 (Symptoms)
原版脚本在校验成功后，直接使用 `\cp -a "$TMPDIR"/* /usr/share/v2ray`。
由于 OpenWrt 环境下 `/tmp` (`$TMPDIR` 创建地点，基于 `tmpfs` 内存挂载) 与 `/usr/share/v2ray` (基于 `overlayfs` 或 `ext4` 闪存挂载) 是不同的物理/逻辑文件系统，`cp` 指令会以文件流的形式覆写数据。如果在拷贝中途发生物理断电，`/usr/share/v2ray` 文件夹中的目标文件将被截断，损坏正在运行或即将运行的 `mosdns`/`xray` 进程，引发严重的连环故障（启动环崩溃）。

## 3. 根因分析 (Root Cause)
跨文件系统分区无法执行原生的原子重命名（`rename(2)`）系统调用。直接向现网业务目录发起流式的写操作（`cp` 覆盖），在没有事务或影子文件的保护下，写操作是非原子的。如果在写操作期间终端电源，原本旧有的好数据早已被阶段性覆写破坏。

## 4. 实施修复 (Resolution)
重构 `mosdns.sh` 中的 `geodat_update` 函数，引入 **Shadow-folder atomic switches (影子替换法)**：
1. **同级挂载点过度 (Staging)**：使用 `mkdir -p /usr/share/v2ray_tmp` 在真正的目标同级目录（即同一个物理文件系统 / overlayfs 上）创建影子过度文件夹。
2. **跨分区拉取 (Cross-FS Copy)**：把位于内存卷 `$TMPDIR` 下的新数据 `cp` 操作重定向到 `/usr/share/v2ray_tmp` 中。如果此阶段遭遇断电，被损坏的仅是不足挂齿的影子文件夹。
3. **极速原子切换 (Atomic Rename)**：当且仅当向影子文件夹的数据迁移完美执行 (`$? -eq 0`) 后，立刻使用 `mv -f /usr/share/v2ray_tmp/geoip.dat /usr/share/v2ray/geoip.dat` 与 `mv -f /usr/share/v2ray_tmp/geosite.dat /usr/share/v2ray/geosite.dat` 将数据“瞬移”至现网业务目录。
在同一个文件系统内，覆盖式的 `mv` 指令对应的底层 Unix API 为 `rename(2)`，这是一个微秒级别的原子操作，完全切断了被断电“撕裂”的时间窗口。

## 5. 链路与影响验证
通过此修改完成了数据更新环节的防断电级别容灾：
- 完美规避 `cp` 进行中导致的“半截文件”污染。
- 旧数据只在最后一刻（也就是新数据已经就绪在同一个硬盘下）才会被系统内核原子替换机制覆写。
- 引入 `[UPD-B004-①]` 追踪由于磁盘写满导致的阶段失败场景。
