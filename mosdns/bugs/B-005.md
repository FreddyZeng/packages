# 🐛 Bug Report: B-005

## 1. 根本目标 (Goal)
成功编译并打包 OpenWrt 固件，包含按配置定义的所有依赖和插件，如 `luci-app-mosdns`。

## 2. 根本原因 (Root Cause)
`luci-app-mosdns` 在源代码目录 (`root/usr/share/v2ray/`) 中强行预置了 `geoip.dat` 和 `geosite.dat` 模型，但其在 `Makefile` 中也正确声明依赖了标准系统包 `+v2ray-geoip +v2ray-geosite`。这导致了在此插件构建打包或者最终 rootfs 组装阶段，opkg 发现两个不同的插件尝试向宿主文件系统的同一个位置灌入相同路径的文件，触发了安全防护即重名冲突 (`check_data_file_clashes`)，最终报错 `make` 进程退出。

## 3. 根本错误 (The Error)
- Error: `opkg_install_cmd: Cannot install package luci-app-mosdns` due to clashes with `v2ray-geoip` and `v2ray-geosite`.

## 4. 表层症状 (Symptom)
用户在运行 `10_编译固件.txt` 流程编译期间，整个工具链在最后关键的 `package/install` 阶段以 Error 255/Error 2 硬分叉并中止，固件镜像打包全面下线。

## 5. 修复方案 (Resolution)
采用 KISS 原则，从 `luci-app-mosdns` 代码库直接删除引发冲突的 `root/usr/share/v2ray` 文件夹或预置的 dat 文件。既然 Makefile 原本就依赖了 `v2ray-geoip` 和 `v2ray-geosite` 上游包，完全交接由上游标准库提供该依赖数据集即可，从而彻底干掉发生碰撞的源头。

## 6. 验证 (Verification)
应用补丁后再次执行 `make`，因为移除了多余的载荷资源，打包阶段不再发生文件层面的碰撞，`luci-app-mosdns` 可以平滑安装进 rootfs。
